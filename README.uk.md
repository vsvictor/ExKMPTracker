# ExKMPTracker 1.1.2

[English](README.md)

Зміни відносно 1.0.0 зібрано в [журналі](docs/changelog.uk.md).

Окрема **бібліотека автомобільного трекінгу Kotlin Multiplatform** для Android
та iOS. Android використовує нативний Foreground Service типу location;
iOS — фоновий Core Location із режимом automotive navigation. Спільні EKF,
валідація, утримання зупинки, запис і FIFO-доставка керуються через BLoC.
Трекер не залежить від стану UI хоста, доки ОС дозволяє його виконання.

Це бібліотека, не застосунок із мапою та не самостійний APK. Адресу сервера,
облікові дані та підтверджену особу водія не вбудовано.
Ця реалізація охоплює **етапи 1 і 2 CoopNav** із `XRNavi/docs/Req.md`.
Початково: `section(1, true)`, `section(2, false)`, `section(3, false)`.
Етап 2 потребує явно інжектованих CV-моделі, калібрування та конфігурації сервера;
MoQ-офлоад (етап 3) не реалізований, увімкнути його неможливо.

## Можливості

- Високоточна нативна геолокація, точності доплерівської швидкості/курсу,
  орієнтаційно-компенсовані дані руху; додаткові сенсори активності та кроків.
- Чотирикомпонентний EKF із формою Джозефа, χ²-відкиданням викидів,
  пригніченням дрейфу на стоянці та обмеженим явно позначеним прогнозом.
- Надійна захищена офлайн-черга, поділ за власником, 16-байтові випадкові ID,
  JSON-RPC-доставка щонайменше один раз і точні FIFO-підтвердження.
- Перевірки часу, mock і телепортації; на Android — евристики GNSS-завад,
  коли обладнання надає потрібні вимірювання.
- Інжекція транспорту, годинника, сховища, журналу та додаткового road matcher;
  спостережуваний `TrackerState`. Глобального singleton runtime немає.
- Лічильники UID-трафіку Android від створення лічильника runtime; непідтримуваний
  повний облік трафіку iOS явно повертає помилку.
- Необов'язкові калібрований нативний YOLO, автентифікована синхронізація сусідів
  і кооперативна EKF-корекція з перевіркою інновації та незалежною живою
  автономною позицією. Див. [перемикачі](docs/coopnav.uk.md) і
  [налаштування CV](docs/vision.uk.md).

## Інтеграція

1. Хост виконує вхід та успішний `getShift`, не запускаючи сенсори.
2. Отримує дозволи точної геолокації з поясненням для користувача.
3. Створює сесію лише з підтвердженої серверної відповіді:

```kotlin
val session = TrackingSession.fromConfirmedShift(
    sessionId = authenticatedSessionId,
    performerId = shift.performerId,
    brandId = shift.brandId,
)
```

4. Налаштовує нативні залежності та запускає трекер із видимого застосунку.
   Runtime володіє сенсорами й після переходу UI у фон.
5. Спостерігає за `TrackerState`, показує `error`/`rejection` користувачу
   та явно зупиняє трекінг після завершення зміни.

Повні інструкції: [Android](docs/android.uk.md), [iOS](docs/ios.uk.md),
[алгоритм і протокол](docs/algorithm.uk.md).
Використовуйте `RpcTrackingTransport(hostRpc)` із реалізацією
`TrackingRpcTransport(call/notify)` поверх наявного автентифікованого з'єднання
JSON-RPC-2-Client-KMP хоста. Ядро не відкриває мережевих з'єднань.
Для Swift реалізуйте `TrackingRpcClient` та передайте
`HostRpcTrackingTransport(client:)` нативному runtime. Дивіться
[контракт CoopNav](docs/coopnav.uk.md) і [SQLCipher-сховище](docs/storage.uk.md).
Попередні Ktor-адаптери перенесені до окремого необов'язкового модуля
`:tracker-http`; ядро CoopNav їх не використовує й не потребує.

У `settings.gradle.kts` проєкту-споживача додайте composite build:

```kotlin
includeBuild("/Users/victor/ExKMPTracker")
```

Потім — `implementation("com.exkmptracker:tracker:1.1.2")` у потрібному
KMP source set або Android-модулі. Версії Kotlin/AGP мають бути сумісні
з цією збіркою. Для Swift зберіть і підключіть XCFramework за інструкцією iOS.

## Збирання

Потрібні JDK 21, Android SDK 37; для Apple-цілей — Xcode з iOS SDK.
Wrapper використовує Gradle 9.5.1. Вкажіть власний шлях SDK у
`local.properties` (`sdk.dir=...`) або `ANDROID_HOME`.

```sh
./gradlew :tracker:jvmTest
./gradlew :tracker:assembleAndroidMain
./gradlew :tracker:assembleExKMPTrackerReleaseXCFramework
```

`commonTest` містить детерміновані числові тести, перевірки валідації,
тротлінгу, нерухомості, гонок сесії, таймаутів та доставки. Тести винесені
в окремі `tests.kt`, а не розміщені в реалізації. Фактична точність та
тривалість роботи у фоні потребують еталонних маршрутів і реальних пристроїв.

## Межі точності та фонової роботи

Гарантованої метрової точності за поганої видимості супутників, у міських
каньйонах, підміні сигналу чи довгих тунелях немає. Трекер показує
невизначеність, відкидає неякісні дані та припиняє прогноз після 15 секунд
або за похибки > 100 м. Фільтр не створить відсутню GNSS-інформацію.
Прив'язування до доріг та RTK-корекції не ввімкнено.

Дозволи, постійне сповіщення Android та фоновий режим iOS обов'язкові.
Примусове завершення, системні обмеження чи вимкнена геолокація можуть
зупинити трекінг. Платформи не гарантують точного 1 Гц чи безперервності.
Хост має пояснювати фонове відстеження та виконувати вимоги приватності
й магазинів застосунків.
